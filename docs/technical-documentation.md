## 1. Overview

A static, single-page personal portfolio built with HTML5, CSS3 and vanilla
JavaScript. It has no dependencies, no build step and no backend: the browser
loads three files and runs.

Assignment 2 builds on the Assignment 1 site. What changed:

| Area | Assignment 1 | Assignment 2 |
| --- | --- | --- |
| Projects | Category filter only | Category filter **and** live search, a result count, and an empty state with a reset button |
| Data | Everything hard-coded | A "Latest on GitHub" list fetched live from the GitHub REST API, with loading, error, retry and empty states |
| Motion | Scroll reveal, hover lifts | Plus fade-in when cards reappear, staggered repo cards, a shake on invalid form fields and an animated success message |
| Content | — | New experience entry: AIAA Design/Build/Fly team |

| Property | Value |
| --- | --- |
| Type | Static single-page site |
| Dependencies | None (Google Fonts and the GitHub API are the only external requests) |
| Build step | None |
| Backend | None — the contact form is validated client-side |
| Total page weight | ~90 KB including the portrait and fonts |

### Architecture

Strict separation of concerns — each file has exactly one job:

```
index.html   →  structure and content   (what the page says)
styles.css   →  presentation            (what the page looks like)
script.js    →  behaviour               (what the page does)
```

All visible content lives in `index.html` rather than being generated by
JavaScript. This keeps the content readable without running the site, gives
search engines and screen readers real markup to work with, and means a failure
in the script degrades the page instead of emptying it.

## 3. HTML

### Document structure

```
<header class="nav">          sticky navigation, theme toggle, hamburger
<main id="main">
  <section id="hero">         name, rotating roles, CTAs, portrait
  <section id="stats">        four animated figures
  <section id="about">        required — intro, tagline, portrait
  <section id="skills">       five grouped tag lists
  <section id="projects">     filter bar, search box, seven project cards,
                              and the live "Latest on GitHub" list
  <section id="experience">   ordered-list timeline
  <section id="contact">      required — validated form + contact cards
<footer class="footer">
```

The three required sections (About, Projects, Contact) are present; the rest are
the permitted extra sections.

### Semantics and accessibility

| Decision | Reason |
| --- | --- |
| `<header>`, `<nav>`, `<main>`, `<section>`, `<footer>` | Landmark navigation for assistive technology |
| Skip link as the first focusable element | Lets keyboard users jump past the navigation |
| `<article>` per project, `<ol>` for the timeline | The timeline is genuinely ordered; projects are self-contained |
| Descriptive `alt` on every image | Decorative background blobs use `aria-hidden="true"` instead |
| `<label for>` on every input | Clicking the label focuses the field; screen readers announce it |
| `aria-describedby` linking inputs to their error paragraph | The error is read out with the field, not lost |
| `role="alert"` on errors, `role="status"` on the success message | Validation feedback is announced without moving focus |
| `aria-pressed` on the theme toggle and filter buttons | Conveys on/off state, not just a visual highlight |
| `aria-expanded` / `aria-controls` on the hamburger | Announces whether the menu is open |
| `width` and `height` on every `<img>` | Reserves space so the layout does not shift while images load |
| `loading="lazy"` below the fold | Off-screen images are not fetched until needed |

## 4. CSS

The stylesheet is ordered **tokens → base → components → responsive →
accessibility**, so a rule never depends on something defined after it.

### 4.1 Design tokens and theming

Every colour in the file is a custom property defined once on `:root`. Dark is
the default; the light theme redefines *only* the tokens:

```css
:root {
  --bg: #0a0a12;
  --text: #e9e9f2;
  --accent2: #22d3ee;
  /* …17 tokens total */
}

:root[data-theme="light"] {
  --bg: #f6f6fb;
  --text: #14142b;
  --accent2: #0e7490;   /* darkened: cyan fails contrast on white */
}
```

Because no layout rule mentions a literal colour, switching themes is one
attribute change on `<html>`. The accent colours are not reused verbatim between
themes — `#22d3ee` scores about 1.9:1 against a white card, well below the WCAG
AA minimum of 4.5:1, so the light theme uses `#0e7490` (≈5.1:1) instead.

### 4.2 Layout

| Where | Technique | Why |
| --- | --- | --- |
| Navigation bar | Flexbox | One row, items pushed to both ends |
| Hero, About | Grid, `1.3fr 0.7fr` | Two asymmetric columns that collapse to one |
| Stats, projects, contact cards | Grid, fixed column counts | Predictable, even rows |
| Skills | Grid, `repeat(auto-fit, minmax(185px, 1fr))` | Fits all five groups on one row at desktop width and reflows without any media query |
| Tag and chip lists | Flexbox with `wrap` | Items are different widths |

Fluid sizing is used instead of extra breakpoints wherever possible:
`clamp(2.8rem, 7vw, 5.2rem)` for the `h1`, `clamp(16px, 5vw, 64px)` for the
navigation padding.

### 4.3 Responsive strategy

Three breakpoints, each chosen because the layout actually breaks there:

| Breakpoint | Changes | Why here |
| --- | --- | --- |
| **≤ 1024px** | Navigation becomes an off-canvas panel behind a hamburger; projects go to 2 columns; contact becomes 1 column | The five-item nav starts crowding the logo well before 768px, so the menu collapses early rather than letting it overflow |
| **≤ 900px** | Hero becomes a single centred column with the portrait first; stats 2 columns; About stacks | The 1.3fr hero column can no longer hold a readable line length |
| **≤ 600px** | Everything single-column; portrait 280px → 220px; form padding reduced | Standard phone width — 375px must not scroll horizontally |

The layout was checked at 1440px, 768px and 375px.

### 4.4 Performance notes

- **Animations are `transform` and `opacity` only.** Both are composited by the
  GPU and skip layout and paint, so the background blobs and hover lifts do not
  cause reflow.
- **`filter: blur(90px)` is applied to three fixed elements only.** They are
  never re-rendered because they animate with `transform`.
- **Fonts** use `preconnect` to `fonts.gstatic.com` and `display=swap`, so text
  is visible immediately in the system fallback rather than invisible while the
  webfont downloads.
- **Thumbnails are SVG**, ~1 KB each instead of ~40 KB per JPEG, and sharp on
  any display.

## 5. JavaScript

`js/script.js` is loaded with `defer`, so it runs after the HTML is parsed —
no `DOMContentLoaded` wrapper is needed. It is organised into nine independent
blocks; none depends on another.

### 5.1 Theme toggle

```
saved choice in localStorage  →  OS preference  →  dark
```

`applyTheme()` sets `<html data-theme>`, swaps the icon, and updates
`aria-pressed` and `aria-label`. An explicit choice is checked before
`matchMedia("(prefers-color-scheme: light)")` because a deliberate click should
outrank the system default, and it persists across page loads.

### 5.2 Time-of-day greeting

Reads `new Date().getHours()` in the visitor's timezone and renders
"Good morning / afternoon / evening" in the hero (< 12, < 18, otherwise).

### 5.3 Typewriter effect

Cycles five role strings, typing at 85 ms per character, deleting at 45 ms, and
pausing 1400 ms on the completed word. It uses a recursive `setTimeout` rather
than `setInterval` precisely because those three delays differ.

### 5.4 Navigation

- A `scroll` listener toggles `.scrolled`, which adds the blurred background.
- The hamburger toggles `.open` on the panel and keeps `aria-expanded` in sync.
  The menu also closes on any link click and on <kbd>Escape</kbd>.
- The active link is tracked by an `IntersectionObserver` with
  `rootMargin: "-45% 0px -50% 0px"`, which shrinks the observed area to a thin
  band across the middle of the viewport so exactly one section is "current".

### 5.5 Scroll reveal

One `IntersectionObserver` at `threshold: 0.12` adds `.in` to each `.reveal`
element, then calls `unobserve()` so it never fires again.

### 5.6 Animated counters

A second observer at `threshold: 0.5` animates each figure from 0 to its
`data-count` value over 60 `requestAnimationFrame` steps, honouring the
`data-dec`, `data-prefix` and `data-suffix` attributes. The HTML contains the
real final values, so the content is correct even if the script never runs.

### 5.7 Project filter and live search

The category buttons and the search box drive one function, `updateProjects()`,
so the two always agree. A card is shown only if it is in the active category
**and** its text contains the search term:

```js
const inCategory = activeCategory === "all" || card.dataset.category === activeCategory;
const matches = !term || card.textContent.toLowerCase().includes(term);
card.hidden = !(inCategory && matches);
```

- The search runs on the `input` event, so results update on every keystroke.
  Seven cards is small enough that no debounce is needed.
- Searching `textContent` means the title, description and tech chips are all
  searchable ("flask", "drones", "RAG") without keeping a separate index.
- A live count ("Showing 2 of 7 projects") sits in an `aria-live` region so
  screen-reader users hear the result too.
- When nothing matches, the empty state names the search term and offers a
  **Show all projects** button that clears the search and the filter.
- The filter bar still uses one delegated click listener instead of one per
  button.

### 5.8 Contact form validation

The form carries `novalidate` so the browser's own bubbles are suppressed and
validation behaves identically everywhere.

| Field | Rule |
| --- | --- |
| Name | At least 2 characters after trimming |
| Email | Matches `/^[^\s@]+@[^\s@]+\.[^\s@]{2,}$/` — a TLD of 2+ characters |
| Message | At least 10 characters after trimming |

Rules live in a `rules` object keyed by input `id`, so `validateField()` is one
function for all three fields. On submit the handler calls
`event.preventDefault()`, validates every field, and either focuses the first
invalid input or shows a personalised success message and resets the form.
Errors clear as the visitor types and are re-checked on `blur`.

There is no backend, as the brief specifies — nothing is transmitted.

### 5.9 Latest repositories from the GitHub API

`loadRepos()` requests
`https://api.github.com/users/quhtani-x/repos?sort=pushed&per_page=12`,
drops forks, keeps the six most recently pushed, and renders a card for each
(name, description, language, stars, last update).

| State | What the visitor sees |
| --- | --- |
| Loading | "Loading repositories…" with a small spinner |
| Success | Up to six repo cards |
| No repos | "No public repositories to show yet." |
| Offline / network error (`TypeError` from `fetch`) | "Couldn't reach GitHub. Check your internet connection, then try again." + **Try again** |
| Rate limited (HTTP 403) | Explains GitHub's hourly limit and to retry in a few minutes + **Try again** |
| Any other HTTP error | The status code + **Try again** |

`response.ok` is checked explicitly, because `fetch` only rejects on network
failure, not on a 404 or 500. Cards are built with `createElement` and
`textContent` rather than `innerHTML`, so a repo description can never inject
markup into the page.

### 5.10 Animations

All new motion is CSS keyframes on `transform` and `opacity`. JavaScript only
adds a class, through a small helper that lets the same animation replay:

```js
function replayAnimation(el, className) {
  el.classList.remove(className);
  void el.offsetWidth;   // forces a reflow so the browser restarts the animation
  el.classList.add(className);
}
```

| Animation | Trigger |
| --- | --- |
| `fade-up` | A project card that was hidden comes back after filtering or searching |
| `fade-up`, staggered 60 ms | Repo cards appearing after the fetch |
| `shake` | Each invalid field when the form is submitted |
| `slide-in` | The success message after a valid submit |

Every one of them is switched off under `prefers-reduced-motion: reduce`.

## 6. Browser support

| Feature | Minimum support |
| --- | --- |
| CSS Grid, Flexbox, custom properties | Chrome 49+, Firefox 31+, Safari 9.1+, Edge 16+ |
| `IntersectionObserver` | Chrome 51+, Firefox 55+, Safari 12.1+ |
| `fetch`, `async`/`await`, `replaceChildren()` | Chrome 86+, Firefox 78+, Safari 14+ |
| `backdrop-filter` | Chrome 76+, Safari 9+ (`-webkit-` prefix included) |
| `aspect-ratio`, `clamp()` | Chrome 88+, Firefox 89+, Safari 15+ |

Every feature is supported in all major browsers released since 2020. Verified
in a Chromium-based browser on macOS at the widths listed in section 4.3.
`backdrop-filter` is the only progressive enhancement: where it is unsupported
the navigation bar falls back to a solid tinted background, which is still
legible.

## 8. Known limitations

- **The contact form does not send anything.** The brief states no backend is
  required. Adding one means a form service (Formspree, EmailJS) or a serverless
  function.
- **Project thumbnails are placeholder artwork**, not screenshots of the running
  projects, as the brief permits.
- **The GitHub API allows 60 unauthenticated requests per hour per IP.** A
  visitor who reloads the page many times will hit the rate-limit message.
  Caching the response in `sessionStorage` would fix that.
- **Google Fonts is an external request.** Self-hosting the two font families
  would remove it at the cost of ~60 KB in the repository.
